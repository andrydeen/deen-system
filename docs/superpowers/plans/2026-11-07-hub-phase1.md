# Hub Phase 1 (Router + Workers core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `hub` plugin in `deen-system` so one Router session can dispatch, steer, watch, evaluate and merge background `claude -p` workers across projects, with a console board and Telegram mirroring, and prove it end to end on one real WillBuilder ticket.

**Architecture:** A bash CLI `hub` (subcommands backed by small bash/python3 modules) owns all state under `$HUB_DIR` (default `~/Projects/Hub`): ticket files with YAML frontmatter, `INDEX.md`, and `.runs/<ticket>/` per worker. Workers are `claude -p` processes started by `hub dispatch`, interrupted/resumed by `hub send`, observed by `hub board`/`hub watch`. The Router is a custom agent (`agents/hub-router.md`) with no Edit/Write tools whose only write path is the CLI. All CLI behaviour is tested against a fake `claude` binary so tests never call the API.

**Tech Stack:** bash 3.2-compatible shell, python3 standard library only, git, Claude Code 2.1.319 (`claude -p`, `--agent`, stream-json), Claude Code plugin layout (`.claude-plugin/plugin.json`, `agents/`, `skills/`).

**Spec:** `/Users/andrydeen/Projects/Deen-setup/deen-system/docs/superpowers/specs/2026-11-07-hub-router-workers-design.md` (Phase 1 of §9; Phase 0 spike is Task 0 here. Phases 2 and 3 get their own plans.)

## Global Constraints

- macOS default shell tooling: scripts must run under bash 3.2 (no associative arrays, no `mapfile`), no `flock`; locks are `mkdir`-based (spec §7).
- python3 standard library only, no pip dependencies.
- Every path is quoted; project paths contain spaces (`final project files`).
- The plugin ships publicly: nothing under `plugins/hub/` may contain any string from `scripts/forbidden-list.txt` (notably `project-dashboard`, the author's full name, `Deen-setup/deen-system`). Din-specific data (project list, chat ids, WillBuilder rules) lives only in `$HUB_DIR`.
- Worker invocation exactly as spec §4: `claude -p "<prompt>" --agent hub-worker --session-id <uuid> | --resume <uuid> --append-system-prompt "<rules>" --permission-mode auto --allowedTools "Write,Edit,Read,Glob,Grep" --output-format stream-json --verbose --max-turns N --max-budget-usd X [--model m]`. Never `bypassPermissions`. (Spike C′: without `--allowedTools` the auto classifier denied a burst of parallel `Write` calls and the round died with no report; `Bash` stays under the classifier.)
- Spike facts every task must respect (`docs/superpowers/specs/2026-11-07-hub-spike-results.md`): a SIGINT-ed `claude -p` exits **0** with a final line `{"type":"result","subtype":"error_during_execution","result":null,...}`; an interrupted round is recognised only by the `interrupted` marker dispatch writes before sending the signal. `permission_denials` can be `[]` while every tool call was denied; denials are `tool_result` blocks with `is_error: true` and text starting `The user doesn't want to proceed`.
- Defaults (spec §7): `HUB_MAX_WORKERS=4`, `HUB_MAX_TURNS=150`, `HUB_MAX_BUDGET_USD=8`, stalled after 15 min silence, loop after 8 edits of one file in 30 min or the same tool call repeated more than 10 times, retries 3 with 30/60/120 s backoff.
- Worker report block is exactly four lines, `Status:`, `Eval:`, `Files:`, `Note:` or `Question:` (spec §4); statuses `ready | blocked | failed | dropped`.
- Ticket statuses: `open, running, waiting, blocked, ready, done, dropped, hold, failed, stopped` (spec §4 plus `failed`/`stopped` from the CLI).
- Worktrees: `<repo>/.claude/worktrees/<ticket>` on branch `hub/<ticket>` from `main` (or `base: head`); only for projects whose `projects.yaml` entry says `isolation: worktree`.
- Telegram messages ≤ 100 words; approval records in approval-gate format under `$APPROVALS_DIR` (default `~/.deen-system/approvals`).
- Commit after every task; message prefix `feat(hub):` / `test(hub):` / `docs(hub):`; end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A worker's final message without the four-line block (the model forgot): the ticket must become `unknown-report`, never `ready`. Pinned in Task 3 (`test_events_missing_block`) and Task 4 (`test_dispatch_unknown_report`).
2. A brief containing `"`, `'`, backticks, `$VAR` and newlines must reach `claude -p` verbatim with no shell expansion. Pinned in Task 4 (`test_dispatch_prompt_verbatim`).
3. A project path with spaces, for dispatch, worktree creation and merge. Pinned in Task 4 (`test_dispatch_path_with_spaces`) and Task 8 (`test_merge_none_path_with_spaces`).
4. A crashed round leaves a slot dir and a `pid` file behind: the next dispatch must reclaim the slot instead of queuing forever. Pinned in Task 4 (`test_dispatch_reclaims_stale_slot`).
5. Two `hub new` calls at the same moment must not allocate the same ticket id. Pinned in Task 2 (`test_new_concurrent_ids`).

### Task 4: `hub dispatch`

**Files:**
- Create: `plugins/hub/scripts/lib/dispatch.sh`, `plugins/hub/tests/test_04_dispatch.sh`
- Modify: `plugins/hub/scripts/hub` (route `dispatch`)

**Interfaces:**
- Consumes: `tickets.py get/set/note/projects`, `events.py final`, `hub_lock`, `$HUB_DIR/config`.
- `hub dispatch T-001 [--wait]` → runs a *round* in the background and returns immediately (prints `dispatched T-001 round 1 pid NNN`); with `--wait` blocks until the round ends and exits with the claude exit code. Round procedure (function `hub_round <ticket> <prompt-file>` reused by Task 5):
  1. `.runs/T-001/` with `session-id` (uuid, lowercase), `round` counter, `project` (resolved cwd), `started`.
  2. Isolation `worktree`: `git -C "$repo" worktree add -b "hub/T-001" "$repo/.claude/worktrees/T-001" "<base>"` (base = ticket `base: head` → `HEAD`, else the project's `main`); idempotent if it exists; writes `.runs/T-001/worktree`. Isolation `none`: cwd = project path, no git commands.
  3. Slot: try `mkdir "$HUB_DIR/.runs/.slots/N"` for N in 1..`HUB_MAX_WORKERS`, writing `$slot/pid`; a slot whose `pid` is dead is removed and retried; none free → `status queued`, retry every 10 s.
  4. Command: `WORKER_AGENT_MODE=agent` → `--agent hub-worker`; `inline` → `--model "<ticket model>" --append-system-prompt-file "$HUB_PLUGIN_ROOT/agents/hub-worker.md"`. Always `--append-system-prompt "$(sed "s/{{TICKET}}/T-001/g" templates/worker-rules.md)"`, `--session-id` on round 1 else `--resume`, `--permission-mode auto --allowedTools "Write,Edit,Read,Glob,Grep" --output-format stream-json --verbose --max-turns "$HUB_MAX_TURNS" --max-budget-usd "$HUB_MAX_BUDGET_USD"`, `--model` when the ticket sets one and mode is `agent`. The prompt is passed as a single argument read from the prompt file (`-p "$(cat "$pf")"`), stdin `< /dev/null`, stdout `>> events.jsonl`, stderr `>> stderr.log`.
  5. Writes `pid`, `status running`, ticket `status running`, log line, and appends `<time> running T-001` to `$HUB_DIR/.runs/events.log`.
